# 构想：Catalog 二期 —— treg 托管验证凭证

> 自 `REFACTOR-PLAN.md` §3.3 抽出。这是构想，未排期，其中任何内容都不是架构改造的完成条件。它存在是为了让改造计划里不残留带细节的非目标。

二期可以让 treg 本身成为验证凭证通道：

1. 一个供应商创建专用验证团队，把测试 key 存成连接。
2. treg 在保存时运行基础活体验证。
3. 供应商只授权验证机器调用指定工具。
4. 验证流水线通过 treg 代理调用真实 API，维护者和脚本都看不到明文 key。
5. 供应商删除连接或移除验证身份即可撤销权限。

附带的好处：供应商亲自经历客户使用 treg 的真实路径。

实现前必须满足以下全部条件：

- 验证身份拥有工具级最小权限，不继承团队的默认调用权。
- 它不能读取 secret、创建本地运行授权，或改动工具绑定。
- 每次运行锁定允许的 host、工具版本和配置快照；运行中途任何一项都不可替换。
- 优先使用独立验证环境（生产内的独立组织仅作过渡态），并设置单次和每日费用上限。
- 每次调用保留脱敏审计记录，报告与凭证撤销可互相交叉印证。
